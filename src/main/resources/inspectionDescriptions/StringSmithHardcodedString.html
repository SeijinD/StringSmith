Reports hardcoded text the user sees and offers a quick-fix that moves it into strings.xml (Android res/values or Compose Multiplatform composeResources/values), picks the right reference for the context and adds the imports.

What is reported

  • Strings inside a @Composable, e.g. Text("Hello"), contentDescription = "Close", in any source set (commonMain, androidMain, desktopMain, ...)
  • Strings passed to UI calls anywhere: Toast.makeText, Snackbar.make, showSnackbar, setText, setTitle, setMessage, dialog buttons, notification titles and text
  • Strings assigned to UI properties: textView.text = "...", title = "..."
  • Text attributes in layout, menu, navigation, preference and shortcut XML (android:text, hint, title, label, ...)
  • android:label and android:description in AndroidManifest.xml

What is not reported

  • Keys, routes and tags inside a @Composable: Modifier.testTag, navigate, key, remember, resource paths, comparisons
  • Strings in other Kotlin code, such as intent extras, preference keys or ViewModel constants. Enable Hardcoded string in non-UI code to see those.
  • Tests, generated code under build/, Gradle scripts, buildSrc / build-logic, benchmark and baseline-profile modules
  • const val, annotation arguments, exception messages, logging calls, previews (including multipreview annotations and PreviewParameterProvider)
  • Strings without letters ("--", "100", "$count"), strings shorter than the minimum length or matching an exclusion pattern
  • XML values that are already references (@string/..., ?attr/...)

Example

Before

@Composable
fun Greeting() {
    Text("Hello, world!")
}

After

@Composable
fun Greeting() {
    Text(stringResource(R.string.hello_world))
}

Detection is based on names, not types, so a custom composable that takes an ID as its first argument may still be reported. Exclusion patterns, the minimum length and the replacement style are configured in Settings | Tools | StringSmith.
