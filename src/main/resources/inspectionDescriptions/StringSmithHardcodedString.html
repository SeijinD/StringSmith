Highlights hardcoded string literals in Kotlin code and XML layouts that could be moved into the Android res/values/strings.xml resource file. Provides a one-click quick-fix that performs the extraction, picks the right replacement style for the surrounding context, and adds the required imports.

What gets highlighted

  • Kotlin string literals (Compose, Activities, Fragments, plain Kotlin)
  • XML attribute values in layout files

How the quick-fix adapts

Context Replacement
@Composable stringResource(R.string.key)
Activity / Fragment / Service getString(R.string.key)
Other Kotlin code R.string.key
XML layout attribute @string/key

Compose example

Before

@Composable
fun Greeting() {
    Text("Hello, world!")
}

After

import androidx.compose.ui.res.stringResource
import com.example.app.R

@Composable
fun Greeting() {
    Text(stringResource(R.string.hello_world))
}

The matching <string name="hello_world">Hello, world!</string> entry is added to the selected module's values/strings.xml, and the stringResource and R imports are inserted in alphabetical order.

XML layout example

Before

<TextView
    android:text="Welcome" />

After

<TextView
    android:text="@string/welcome" />

What gets skipped

  • Shorter than the configured minimum length
  • Matching any user-defined exclusion regex
  • Inside a @Preview composable (when that setting is on)
  • Kotlin templates with ${'$'}-expressions
  • XML values starting with @ or ? (already references)

Opt-in

This inspection is off by default. Enable it in Settings | Tools | StringSmith – Android Strings Toolkit → Inspection. Configure key prefix, naming convention, replacement style per context, locale propagation defaults, exclusion patterns, and Compose @Preview exclusion in the same panel.
